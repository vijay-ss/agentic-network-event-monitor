SECURITY LOG GENERATION - PRODUCTION PROMPT

Generate realistic hybrid SIEM/Network security logs in JSON format simulating real-world corporate environments.

=== REALISM REQUIREMENTS ===

SEVERITY DISTRIBUTION (strictly follow):
- 85% INFO (routine operations)
- 10% LOW (minor issues, policy violations)
- 4% MEDIUM (auth failures, suspicious patterns)
- 1% HIGH (detected attacks, escalating threats)
- <1% CRITICAL (active incidents, rare)

DATA QUALITY (include realistic imperfections):
- 5-10% malformed logs (missing fields, truncated descriptions, parsing errors, encoding issues)
- 1-3% duplicates: mostly near-duplicates (different IDs, timestamps within seconds), some exact duplicates (100% identical)
- Occasional nulls for geo_location, user_agent, destination_domain
- Subtle inconsistencies (bytes_sent > 0 on BLOCK, duration_ms: 0 or -1)

TIME DISTRIBUTION:
- Span multiple hours with varying density
- Spread timestamps realistically (not clustered)
- Show gradual attack escalation if attacks present

EVENT MIX:
- 85-90% mundane traffic (DNS, HTTPS, backups, health checks, file access)
- 10-15% security-relevant (blocks, failed auth, scans)
- Attacks should build over time, not instant detection

=== LOG STRUCTURE ===

{
  "logs": [
    { /* log object */ }
  ]
}

=== CORE FIELDS ===

ALWAYS INCLUDE:
- id (string), timestamp (datetime), source_ip (string), destination_ip (string), source_port (integer), destination_port (integer)
- protocol (string), application (string), action (string), bytes_sent (integer), bytes_received (integer), packet_count (integer), duration_ms (integer)
- event_type (string), severity (string), user (string), correlation_id (string), device_name (string), vlan_id (integer)
- geo_location (string), user_agent (string), response_code (integer), threat_indicators (string), rule_id (string), description (string)

NETWORK IPS (use realistic ranges):
- Internal: 10.x.x.x, 172.16-31.x.x, 192.168.x.x
- Cloud: AWS (52.x, 54.x), GCP (35.x, 142.250.x), Azure (13.x, 20.x)
- CDN: Cloudflare (104.16-31.x), Akamai
- Legitimate: GitHub (140.82.x), Microsoft (13.x), Google (142.250.x)
- VPN pools: 10.200.x.x
- Guest: 172.20.x.x
- IoT: 10.50.x.x

DEVICE NAMES (realistic patterns):
- Workstations: WS-DEPT-USER-## (e.g., WS-MKTG-JD-042, LAPTOP-ENG-ASMITH)
- Servers: SQLPROD01-CLUSTER-A, WEB-APP-LB-02, DC-PRIMARY-NYC
- Cloud: aws-ec2-i-0abc123def, azure-vm-prod-web-01
- Network: FW-DMZ-PRIMARY, SW-CORE-01, AP-FLOOR3-12
- IoT: HVAC-CONTROLLER-02, PRINTER-FLOOR2-05

USERS (realistic types):
- Regular: firstname.lastname, flastname
- Service: svc_backup, sa_monitoring, service_account_elk
- Contractors: contractor_ext_##, temp_username, ext-vendor-name
- Automation: bot_deploy, automation_jenkins, iot_service

VLANS:
- 1=DMZ, 50=guest, 100=workstations, 150=developers, 200=servers, 300=monitoring, 400=IoT, 999=quarantine

=== OPTIONAL ENRICHMENT FIELDS ===

Use when relevant to log source/type:

log_metadata (SIEM-collected logs):
{
  "collector": "splunk-forwarder-03",
  "source_type": "firewall|edr_agent|ids|vpn_gateway|dns_server",
  "ingestion_time": "ISO8601",
  "pipeline": "network_events|endpoint_security|threat_detection"
}

network_details (network segmentation):
{
  "network_segment": "DMZ|CORPORATE_LAN|VPN_POOL|GUEST_WIFI|SERVER_FARM|IOT_DEVICES",
  "subnet": "CIDR",
  "security_zone": "trusted|untrusted|quarantine|isolated"
}

connection_state: "ESTABLISHED|CLOSED|SYN_SENT|TIME_WAIT" (TCP only)
tcp_flags: "SYN|ACK|FIN,ACK|RST|PSH,ACK" (TCP only)

policy_violation (when action=BLOCK):
{
  "policy_name": "CORP-FW-001",
  "violation_type": "unauthorized_protocol|malicious_content|geo_restriction",
  "policy_severity": "low|medium|high|critical"
}

asset_tags: ["production", "PCI_scope", "critical_system", "SOC2_compliant", "development"]

session_details (RDP, VPN, SSH):
{
  "session_start_time": "ISO8601",
  "session_end_time": "ISO8601",
  "session_duration_seconds": 7200
}

resource_utilization (EDR/endpoint logs ~30% of logs):
{
  "cpu_percent": 12.3,
  "memory_percent": 34.7,
  "disk_io_percent": 8.2,
  "process_name": "git.exe",
  "process_id": 7823
}

Optional: reason, alert_id, file_hash, malware_family

=== EVENT TYPES ===

COMMON (85-90%):
DNS_QUERY, HTTPS_CONNECTION, FILE_SHARE_ACCESS, HEALTH_CHECK, EMAIL_SEND, DATABASE_QUERY, API_CALL, VIDEO_CONFERENCE, CI_CD_BUILD, CLOUD_UPLOAD, CACHE_ACCESS, METRICS_COLLECTION

BLOCKED/SUSPICIOUS (5-10%):
SSH_ATTEMPT, RDP_CONNECTION_ATTEMPT, SMB_CONNECTION_ATTEMPT, HTTP_BLOCKED, STREAMING_BLOCKED, PORT_SCAN_DETECTED

HIGH SEVERITY (rare):
BRUTE_FORCE_ATTACK, PORT_SCAN_DETECTED, MALWARE_DOWNLOAD_BLOCKED, SQL_INJECTION_ATTEMPT, PRIVILEGE_ESCALATION_ATTEMPT, LATERAL_MOVEMENT_DETECTED, SUSPICIOUS_OUTBOUND_TRAFFIC

CRITICAL SEVERITY (very rare):
DATA_EXFILTRATION_CONFIRMED, MALWARE_EXECUTION_DETECTED, RANSOMWARE_ACTIVE, ROOT_COMPROMISE, BACKDOOR_DETECTED, C2_COMMUNICATION, ZERO_DAY_EXPLOIT

=== USAGE ===

DEFAULT BEHAVIOR:
- Hybrid format: 70% network-only (resource_utilization: null), 30% EDR-enriched
- Realistic time distribution across requested span
- Follow severity ratios strictly
- Include 5-10% malformed, 1-3% duplicates

=== CRITICAL REMINDERS ===

✗ DON'T: Make every event critical, cluster timestamps, use only generic IPs, create perfect clean data
✓ DO: Follow severity ratios, spread time realistically, use varied realistic IPs, include data quality issues
✓ DO: 70% logs are boring routine traffic (DNS, backups, health checks)
✓ DO: Attacks escalate gradually over time (LOW → MEDIUM → HIGH → CRITICAL)
✓ DO: Use realistic device names, usernames, and network segments
✓ DO: resource_utilization only for EDR/endpoint logs (~30%), null for network logs (~70%)
